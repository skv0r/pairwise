# PairWise — карта проекта

Карта мест для живых встреч один на один: разобрать задачи, поймать инвестора, показать B2B SaaS. Не каталог коворкингов и не места для учёбы.

На собесе: «PairWise — карта площадок для pairwise-встреч. Назначаешь не Zoom, а точку на карте».

---

## 1. Для отчёта лабораторной № 1

| Поле | Значение |
|---|---|
| Название | PairWise |
| Проблема | Рабочие разговоры срываются в чат и созвон: нет понятного места, куда назначить 1:1 по делу. |
| Аудитория | Разработчики, фаундеры, люди из B2B SaaS, которые встречаются очно. |
| Главная сущность | Spot — площадка для встречи пары людей. |
| Три функции | Каталог площадок; поиск по типу встречи; сохранение избранных точек. |

Это не StudySpace: объект не «тихое место для конспектов», а место, куда имеет смысл назначить разговор. Это не TheraCity: нет прогулочных маршрутов и фотогорода как сути продукта.

---

## 2. Сущности

### Spot — главная сущность

Площадка на карте. Каталог, динамический маршрут, галерея и метки строятся вокруг неё.

### User — учебный пользователь

Появляется в ЛР2 как объект в React-состоянии. В БД и сессии — позже.

### Bookmark — сохранённая площадка

В ЛР3 это `Set` из id в `useState`. Потом — связь пользователя и Spot.

### Review — отзыв (после ЛР3)

Текст, оценка, тип встречи, для которой площадка подошла.

### OccupancySnapshot — загрузка (после ЛР3)

Насколько людно сейчас или обычно в этот час. Для фильтра «не слишком шумно для питча».

На ЛР2–3 Review и OccupancySnapshot не создаём. Их поля не смешиваем с Spot, чтобы тип лабораторной сущности оставался коротким.

---

## 3. Связи

```
User 1 ── N Bookmark N ── 1 Spot
User 1 ── N Review   N ── 1 Spot
Spot  1 ── N OccupancySnapshot
```

Один Spot подходит для нескольких типов встреч (`meetingKinds`).  
Один пользователь сохраняет много площадок.  
Отзыв всегда про конкретный Spot и про конкретный вид встречи.

ЛР2: связи нет, только массив Spot.  
ЛР3: User в контексте + Bookmark как Set.  
ЛР6–7: User, Bookmark, Review в PostgreSQL.

---

## 4. Типы

### Лабораторные № 2–3 (учебный массив)

Минимум ЛР2: `id`, название, описание, одно своё поле.  
ЛР3 добавляет фото и координаты.

```ts
export type MeetingKind = "tasks" | "investors" | "b2b";

export type Spot = {
  id: string;
  title: string;
  summary: string;
  address: string;
  meetingKinds: MeetingKind[];
  image: string;
  imageAlt: string;
  latitude: number;
  longitude: number;
};

export type DemoUser = {
  name: string;
  email: string;
};
```

Своё предметное поле для отчёта ЛР2: `meetingKinds` (для каких разговоров площадка).  
`address` тоже нужен, но это не отличитель от учебного примера «мест». Тип встречи — отличитель.

### Целевые типы (после подключения БД)

```ts
export type User = {
  id: string;
  name: string;
  email: string;
  passwordHash: string;
};

export type Bookmark = {
  userId: string;
  spotId: string;
  createdAt: string;
};

export type Review = {
  id: string;
  userId: string;
  spotId: string;
  meetingKind: MeetingKind;
  rating: number;
  text: string;
  createdAt: string;
};

export type OccupancyLevel = "quiet" | "moderate" | "busy";

export type SpotFilters = {
  query?: string;
  meetingKind?: MeetingKind;
  occupancy?: OccupancyLevel;
};
```

Пароль в клиентском прототипе не хранится. `passwordHash` появляется только на сервере.

## 6. Страницы

### `/start`

Название PairWise, проблема, аудитория, три функции карточками `FeatureCard`, ссылка в каталог и на `/about`.

### `/about`

Цель, будущий результат к 7-й работе, сущность Spot, список разделов, ссылка на главную.

### `/catalog`

Сетка карточек из массива Spot. На карточке: название, краткое описание, тип встречи, ссылка `/catalog/{id}`.  
Страница серверная. Фильтры по загрузке и отзывам — позже, отдельным клиентским компонентом.

### `/catalog/[id]`

Серверная страница. `await params`, поиск Spot, иначе `notFound()`.  
Показывает адрес, типы встреч, описание, фото (с ЛР3), ссылку назад в каталог.

### `/gallery`

Серверная оболочка + клиентская галерея. Карточки-кнопки с `next/image`, модалка, карта. Клик по метке открывает ту же модалку, что и клик по карточке.

### `/auth/login` и `/auth/register`

Клиентские формы. Учебный прототип, не серверная аутентификация. После успеха — переход в `/cabinet`. Предупреждение, что пароль не проверяется сервером и не сохраняется.

### `/cabinet`

Клиентская страница. Гость видит приглашение войти. Пользователь видит имя, email и выход. Список сохранённых Spot — когда Bookmark будет в данных; в ЛР3 избранное живёт в галерее.

## 7. Компоненты

| Компонент | Где | Зачем |
|---|---|---|
| `FeatureCard` | `/start`, ЛР1 | Типизированные карточки функций, ≥ 3 раза |
| `AppNav` | layout, ЛР2 | `Link` + `usePathname` + `aria-current` |
| `BurgerMenu` | вместо AppNav, ЛР3 | Меню, Escape, фон, фокус, гость/пользователь |
| `DemoAuthProvider` | корневой layout | `user`, `login`, `register`, `logout` |
| `SpotsGallery` | `/gallery` | Выбор Spot, избранное, связь с картой |
| `SpotModal` | портал в `document.body` | Фото, типы встреч, сохранить / войти |
| `SpotMap` | под галереей | Яндекс.Карта, метки, клик → модалка |

Граница `"use client"` только там, где есть состояние, события, эффекты или браузерный API. Страницы каталога и карточки остаются серверными.

## 8. Авторизация (учебный прототип)

Это интерфейс, не защита.

- **Аутентификация** — в ЛР2 не выполняется: пароль не сверяется с БД.
- **Сессия** — нет cookie и серверного пользователя; `useState` сбрасывается при обновлении страницы.
- **Авторизация** — скрытая кнопка не запрещает доступ к данным. `/cabinet` открывается по URL и сама решает, что показать.

Контракт провайдера:

```ts
type DemoAuthContextValue = {
  user: DemoUser | null;
  login: (email: string) => void;
  register: (name: string, email: string) => void;
  logout: () => void;
};
```

`login` собирает пользователя из email. `register` — из имени и email. Пароль не пишется в state, localStorage и файлы.

В модалке ЛР3: если `user` есть — кнопка «Сохранить площадку» / «Убрать». Если нет — ссылка на вход. Подпись: избранное хранится до обновления страницы.

## 11. Сценарии проверки

### Гость (ЛР2)

Открыть `/start` → каталог → две карточки Spot → `/catalog/unknown` даёт Not Found → кабинет предлагает войти → короткий пароль показывает ошибку → учебный вход → имя в меню и кабинете → выход → обновление страницы сбрасывает пользователя.

### Регистрация

Имя, email, пароль, повтор пароля. Несовпадение паролей — ошибка. Успех → `/cabinet`.

### Галерея (ЛР3)

Фото без 404. Карточка и метка открывают один и тот же Spot. Escape, Tab, клик по фону закрывают модалку. Фокус не уходит из диалога. Гость видит ссылку на вход. Учебный пользователь сохраняет площадку. После F5 пользователь и избранное пропадают.

## 12. Что в какую лабораторную

| Лаба | Что появляется |
|---|---|
| 1 | Next.js + TS + App Router, `/` и `/about`, `FeatureCard`, концепция PairWise |
| 2 | `/start`, каталог, `[id]`, auth, cabinet, DemoAuthProvider, `spots.ts`, AppNav, redirect |
| 3 | фото, координаты, `/gallery`, модалка, бургер, Яндекс.Карта, учебное избранное |
| 4 | адаптив, Lighthouse (по курсу) |
| 5–7 | PostgreSQL, Prisma, настоящая сессия, отзывы, фильтры, сохранённые Spot в кабинете |

Не обещать в интерфейсе ЛР2–3, что пользователь «безопасно авторизован» или что избранное «сохранено на сервере».

## 13. Нарастание фич после каркаса

Порядок, когда каркас лаб уже сдан:

1. Фильтр каталога по `meetingKind`: задачи / инвесторы / B2B.
2. Поиск по названию и описанию.
3. Отзывы: оценка и для какого типа встречи площадка сработала.
4. Загрузка: тихо / средне / людно.
5. Кабинет: список сохранённых Spot, не только имя и email.
6. Настоящие пользователь и закладки в БД.

Это уже продукт, а не учебный список мест: сначала выбираешь *зачем* встречаешься, потом *куда* сесть вдвоём.
