# PairWise — карта проекта

Платформа для поиска коворкинг-зон, где можно встретить единомышленников, разобрать тренды и рабочие задачи. Подбор мест идёт по общим интересам, стеку посетителей и проектам.

На собесе: «PairWise — не Zoom и не каталог коворкингов ради стола. Ищешь площадку, где уже сидят люди с похожим стеком».

---

## 1. Для отчёта лабораторной № 1

| Поле | Значение |
|---|---|
| Название | PairWise |
| Проблема | Сложно найти коворкинг-зону для очной встречи с единомышленниками: нет подбора по стеку, интересам и проектам. |
| Аудитория | Разработчики, фаундеры и люди из IT, которым нужны очные встречи по делу. |
| Главная сущность | Коворкинг-зона (Spot) — конкретная площадка для очной встречи. |
| Три функции | Каталог с фильтрами по стеку и области работы; избранное и отзывы; планирование совместного визита. |

Страницы ЛР1: `/` (концепция и три `FeatureCard`) и `/about` (цель, результат, сущность, разделы). Это не TheraCity: нет прогулочных маршрутов и фотогорода как сути продукта.

---

## 2. Сущности

### Spot — главная сущность

Коворкинг-зона: площадка, куда можно прийти на очную встречу. Каталог, карточка места, галерея, карта и избранное строятся вокруг неё. Позже у зоны появляются адрес, фото, координаты, стек и интересы сообщества.

### User — учебный пользователь

Появляется в ЛР2 как объект в React-состоянии. В БД и сессии — позже. Уровни: обычный пользователь, подтверждённый, администратор.

### Bookmark — сохранённая площадка

В ЛР3 это `Set` из id в `useState`. Потом — связь пользователя и Spot.

### Review — отзыв (после ЛР3)

Текст и оценка после визита.

### OccupancySnapshot — загрузка (после ЛР3)

Насколько людно сейчас или обычно в этот час.

На ЛР2–3 Review и OccupancySnapshot не создаём. Их поля не смешиваем с Spot.

---

## 3. Связи

```
User 1 ── N Bookmark N ── 1 Spot
User 1 ── N Review   N ── 1 Spot
Spot  1 ── N OccupancySnapshot
```

Один Spot описывается стеком и интересами посетителей.  
Один пользователь сохраняет много площадок.  
Отзыв всегда про конкретный Spot.

ЛР2: связи нет, только массив Spot.  
ЛР3: User в контексте + Bookmark как Set.  
ЛР6–7: User, Bookmark, Review в PostgreSQL.

## 4. Типы

### Сейчас (учебный массив)

```ts
export type Spot = {
  id: number;
  name: string;
  city: string;
  adress: string;
};
```

Позже: описание, стек, интересы, фото, координаты.

```ts
export type DemoUser = {
  name: string;
  email: string;
};
```

### Целевые типы (после подключения БД)

```ts
export type User = {
  id: string;
  name: string;
  email: string;
  passwordHash: string;
};

export type Bookmark = {
  userId: string;
  spotId: number;
  createdAt: string;
};

export type Review = {
  id: string;
  userId: string;
  spotId: number;
  rating: number;
  text: string;
  createdAt: string;
};

export type OccupancyLevel = "quiet" | "moderate" | "busy";

export type SpotFilters = {
  query?: string;
  stack?: string;
  city?: string;
  occupancy?: OccupancyLevel;
};
```

Пароль в клиентском прототипе не хранится. `passwordHash` появляется только на сервере.

## 5. Карта маршрутов

| Назначение | Каталог | URL |
|---|---|---|
| Главная (ЛР1) | `app/page.tsx` | `/` |
| О проекте (ЛР1) | `app/about/page.tsx` | `/about` |
| Редирект на главную | `app/start/page.tsx` | `/start` → `/` |
| Каталог зон | `app/catalog/page.tsx` | `/catalog` |
| Карточка зоны | `app/catalog/[id]/page.tsx` | `/catalog/0` |

## 6. Страницы

### `/`

Название PairWise, проблема, аудитория, три функции карточками `FeatureCard`, ссылка на `/about`.

### `/about`

Цель разработки, будущий результат, сущность (коворкинг-зона), разделы приложения, предполагаемые функции, ссылка на главную. Бегущая строка в шапке.

### `/catalog`

Список из массива `spots`. Сейчас ссылка с названием зоны на `/catalog/{id}`. Страница серверная. Фильтры по стеку и области работы — позже.

### `/catalog/[id]`

Серверная страница. `await params`, поиск Spot по `Number(id)`, иначе `notFound()`.

### `/gallery`

Серверная оболочка + клиентская галерея. Позже: фото, модалка, карта.

### `/auth/login` и `/auth/register`

Клиентские формы. Учебный протокол, не серверная аутентификация. Регистрация: имя, фамилия, дата рождения, пароль, повтор, согласие на обработку данных. Фон страницы регистрации — `NeatBackground`.

### `/cabinet`

Клиентская страница. Гость видит приглашение войти. Пользователь видит имя и выход. Список сохранённых Spot — когда появится Bookmark.

## 8. Авторизация (учебный прототип)

Это интерфейс, не защита.

- **Аутентификация** — пароль не сверяется с БД.
- **Сессия** — нет cookie; `useState` сбрасывается при обновлении страницы.
- **Авторизация** — `/cabinet` открывается по URL и сам решает, что показать.

Контракт провайдера:

```ts
type DemoAuthContextValue = {
  user: DemoUser | null;
  login: (email: string) => void;
  register: (name: string, email: string) => void;
  logout: () => void;
};
```

Пароль не пишется в state, localStorage и файлы. На клиенте пароли в форме регистрации должны совпадать до отправки.

## 11. Сценарии проверки

### Гость (ЛР1–2)

Открыть `/` → `/about` → назад на главную. Каталог → карточка Spot по id → `/catalog/unknown` даёт Not Found. `/start` открывает главную.

### Регистрация

Имя, фамилия, дата рождения, пароль, повтор, чекбокс согласия. Несовпадение паролей — ошибка. Успех → `/cabinet`.

### Галерея (ЛР3)

Фото без 404. Карточка и метка открывают один и тот же Spot. Escape, Tab, клик по фону закрывают модалку. После F5 учебный пользователь и избранное пропадают.

## 12. Что в какую лабораторную

| Лаба | Что появляется |
|---|---|
| 1 | Next.js + TS + App Router, `/` и `/about`, `FeatureCard`, концепция PairWise |
| 2 | каталог, `[id]`, auth, cabinet, DemoAuthProvider, `spots.ts`, навигация |
| 3 | фото, координаты, `/gallery`, модалка, бургер, Яндекс.Карта, учебное избранное |
| 4 | адаптив, Lighthouse (по курсу) |
| 5–7 | PostgreSQL, Prisma, настоящая сессия, отзывы, фильтры, сохранённые Spot в кабинете |

Не обещать в интерфейсе ЛР2–3, что пользователь «безопасно авторизован» или что избранное «сохранено на сервере».
